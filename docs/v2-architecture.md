# CoC Room V2 架构与路线图

V2 是一条新协议线。V1 记录只能离线查看和导出，不会被原地改写，也不能加入 V2 会话。

## 信任与数据流

```text
独立席位邀请
  seatId + seatSecret ──HMAC challenge──> 房主
                                      认证后
玩家命令 ──WebRTC / WSS──> 房主排序、鉴权、生成连续序号
                           ├─ 授权席位：完整事件
                           └─ 无权席位：仅 eventId/sequence/time 占位

带资源描述符的完整事件 ──> 获授权玩家可请求 coc-room-assets-v1
                              24 KiB chunks / ACK / resume / SHA-256
```

Worker 只提供在线状态、信令和临时应用层中继，不保存聊天历史。协议没有 E2EE；走 WSS 中继时，节点运营者理论上能读到转发明文。席位隔离保证的是无权玩家的 SQLite、日志和导出中没有秘密载荷，不是对中继节点的密码学保密。

## 权威事件与投影

- 房主对所有事件分配全局连续序号。客户端只投影连续前缀，缺口触发单飞补发。
- 同步页最多 500 个视图或 4 MiB，逐页 ACK。完整视图可以替换同序号的脱敏视图，不能反向降级或修改。
- 事件受众只能通过后续 `audience.expanded` 单调扩大。已经发送的正文不能撤回。
- `RoomWorldStateV2` 以纯 reducer 重放实体、Artifact、画板、NPC 面板和音频语义；最终空间状态按房主顺序最后写入生效。
- 玩家新建内容的默认受众由房间设置决定；玩家不能修改受众、锁定或归档。角色所有权绑定稳定 `seatId`，不绑定重连时变化的 WebRTC peer ID。

## 实体、Artifact 与画板

模组的场景、地点、NPC 和线索只是 KP 本机资料。发布时形成独立房间快照，可选择性保留 `sourceRef`。再次发布同一模组版本中的内容时，仅在 `moduleId`、`revision`、`kind`、源 ID 与受众演进均兼容时更新原快照；更新必须保留房间中后来增加的场景呈现、NPC 属性、附件和扩展数据。NPC 不属于地点；一个实体可以没有画板表现，也可以在多个画板出现。

`scene`、`map` 和 `evidence` 共用同一个 SVG 画板引擎：

- `<img>` 显示可选背景，SVG 显示项目、关系线、标签和多边形迷雾。
- 拖拽预览走瞬时消息，只有拖拽结束、连线完成和迷雾笔画完成才成为事件。
- 线索关系板上，所有可见成员可移动未锁定项目并协作连线；场景与地图上，调查员只能移动明确归属自己的既有未锁定角色棋子，不能创建/删除项目、修改其他字段或画关系线。KP 控制其余内容以及受众、背景、迷雾、锁定和归档。
- 画板受众必须是每个被引用实体、Artifact 或 NPC 会话受众的子集。公开画板引用秘密线索会在共享 reducer 中被拒绝。

### 调查流程切片

当前房间实现把一次典型调查固定为可审计事件链：

1. KP 在模组库确认并启用一个精确修订；房间工作台只在 KP 本机读取该修订的完整场景资料。
2. KP 将场景引用拖入地图。房间只收到场景名称、来源引用和画板位置，场景摘要、主持人笔记及原文定位不会随拖拽发送。
3. KP 把已同步角色卡放成棋子；调查员只能移动自己角色对应的未锁定棋子。棋子进入场景区域后，KP 工作台显示进入情况，但不会自动揭示内容。
4. KP 分别确认地点的玩家可见描述和 NPC 的玩家可见摘要，再发布独立房间快照；“公开 NPC 摘要”和“增加 NPC 的画板表现棋子”是两个动作，同一 NPC 可以没有棋子，也可以拥有多个表现棋子。
5. 调查员先描述目标和做法，KP 决定直接推进、当前不可行或锁定目标值、难度与奖惩骰。该申请只能由原席位掷一次，房主安全随机结果与授权参数不一致时 reducer 会拒绝。第一次失败后，同一调查员可用新的做法申请一次强推；只有原检定确实失败、受众一致且尚未强推时才接受。KP 批准前必须写明再次失败的代价，玩家看见代价后仍可放弃，强推本身不能再次强推。
6. 掷骰后，KP 用与该 `requestId` 绑定的 `check.outcome.described` 叙述后果，再按需发布线索的 `revealText`。普通聊天、其他玩家的结果、场景切换或线索发布都不能替代这次结算；模组内的线索解释不会进入公开 Artifact。
7. 每名调查员都可把公开线索非独占地认领到个人线索栏，也可随时取消自己的关注；两者分别记录为 `clue.claimed` / `clue.unclaimed`，不会编辑或归档共享线索。KP 可按房主权威代管某个明确角色的关注状态。公开线索始终保留在线索板，可继续摆放和连线。

场景落图、地点/NPC/线索发布都要求 KP 显式操作。系统只辅助定位与提示，不会因棋子碰撞自动读取或公开模组正文。

## 内容寻址资源

事件只携带 `AssetDescriptorV1`。Rust 将文件规范化、复核并原子写入：

```text
assets/sha256/<hash-prefix>/<sha256>.<ext>
```

静态图片统一为去元数据 WebP，并受输入大小、输出大小、边长和像素数限制；拒绝 SVG 和动画。音频仅接受本地 MP3、Ogg/Opus/Vorbis 和 WAV。接收端重新校验长度、MIME、容器和 SHA-256 后才入库。房主只有在对应席位收到引用该资源的完整事件后才提供字节。

资源授权以稳定 `seatId`、事件序号和完整 `AssetDescriptorV1` 追加写入 SQLite，不依赖当前 peer 或进程内缓存。每个已验证的 24 KiB 入站分块会在 ACK 前写入托管临时文件并同步记录索引；应用重启后沿用原 transfer ID，仅请求缺失分块，完成、取消或确认内容损坏后清理临时记录。仅知道或猜中 `assetId` 不构成下载授权。

音频 Artifact 发布后，可见玩家立即在后台预取并用 `asset.ready` 瞬时确认完整描述符。KP 的播放操作只等待当前在线且属于受众的席位就绪；超时会明确失败而不创建伪同步事件。离线成员不阻塞房间，实际播放仍允许每位玩家本地静音和调节音量。

`.cocmod` 和 `.cocchar` 都是带 manifest 的 ZIP 容器。读取器拒绝路径穿越、符号链接、加密项、重复路径、哈希/MIME 不符、异常压缩比和超限解压。

## AI 边界

文本模组解析和 NPC 回复使用 Python JSON Lines sidecar，不开放独立本地 HTTP 端口。桌面运行时由 Rust 从 Windows Credential Manager 取出 DeepSeek Key；带桥的 KP 网页开发模式则由 Vite 同源固定路由启动的一次性 Python 包装器直接读取同一凭据项。两条路径都只通过 sidecar stdin 注入且不会把 Key 交给网页 JavaScript。没有随机开发会话令牌的普通网页/双端玩家页不具备本地 AI 能力，也不会探测宿主的 Codex 或凭据状态。Codex 使用本机登录，但模型运行在远端服务上。

PDF 数字文本由 `pypdf` 提取，任何提供者都可解析；扫描/低文本页的视觉转写走 Codex：手选页或默认全部低文本页由 PDFium 重新渲染为临时 PNG，经哈希与尺寸复核后作为 `codex exec --image` 初始输入。视觉调用和后续结构化调用均关闭工具、项目规则、技能、应用、网页与环境上下文；视觉结果必须通过独立严格 Schema，按页码注入规范化文本后才进入模组抽取，临时图随执行目录销毁。

NPC 每次调用只构造以下三个值：

1. 当前 NPC 卡；
2. KP 在当前面板明确挂载的资料（最多 64 条）；
3. 当前面板最近的消息（最多 200 条 / 100,000 Unicode 字符）。

NPC 面板创建前由 KP 明确选择全房间或指定调查员席位；候选席位先与 NPC 实体受众求子集，事件层随后仍强制把每条消息改写为会话受众。重放时会从已授权的人类消息事件保存发言时的席位显示名，因此其他席位离线或不在本机 presence 列表中时，面板与导出仍能正确标明发言者，同时无权客户端仍只持有不含名称、角色和正文的顺序占位。

请求结构没有房间公共聊天、完整模组、其他面板、私人笔记、数据库查询、文件路径或工具字段。输出只允许 `spokenText`、`stageDirection` 和 `emotion`。审核模式的结果只在 KP 本机审核；自动发布模式也只能向原面板发言，不能触发骰子、线索、棋子或角色变更。

NPC 属性草稿使用另一条房主本地固定入口，只向提供者发送所选 NPC 的名称、公开描述和 KP 单独填写的补充要求，输出严格限制为 CoC 7 版属性、技能、HP 与可选 SAN。生成完成不会创建房间事件；KP 明确审核后才以新的实体修订发布，若 NPC 在生成期间已被修改则拒绝覆盖并要求重新生成。远端席位协议没有 NPC 属性执行器入口。

Codex 图片使用独立 App Server 执行器，不复用安全文本解析器。每次只接受一种图片任务并生成一个候选；返回文件必须位于执行器拥有的临时目录，通过静态图片验证并导入资源库。绑定到实体或画板、以及发布给席位，都是单独的人工确认动作。

## 进阶地图设计

核心画板保持无规则。下面的能力均以版本化扩展加入，不能改变旧事件含义。

具体分期、扩展模型和性能验收见 [进阶地图路线图](advanced-map-roadmap.md)。

### 下一阶段：地图语义层

- `org.coc-room.map-labels.v1`：SVG 地名、地点锚点、路径和区域轮廓。AI 仍只生成无文字底图。
- `org.coc-room.portals.v1`：从一个画板项目链接到另一个画板及目标视口，用于建筑楼层和城市/室内切换。
- `org.coc-room.layers.v1`：背景、地形、公开标记、KP 辅助标记和迷雾层；KP 层永不进入玩家事件。
- 大图导入时生成内容寻址的多分辨率 WebP 瓦片清单，客户端按视口请求，避免把超大地图一次解码进内存。

### 可选桌面规则扩展

`org.coc-room.grid.v1` 只提供方格/六角格显示、吸附、距离单位和棋子尺寸。它不加入先攻、行动经济、伤害或战斗状态；这些规则不应污染调查型房间的通用画板事件。

### 协作与性能门槛

- 继续使用房主排序和最终操作事件，不在首个扩展中引入 CRDT。只有离线并发编辑成为真实需求时才评估对象级 CRDT。
- 瞬时光标和拖拽预览必须可丢弃、限频且不进入 SQLite；最终操作仍可完整重放。
- 验收至少覆盖 8 客户端、10,000 个 SVG 项目、500 条关系线、100 个迷雾多边形，以及直连/WSS 两条资源路径。
- 任何新引用都必须通过受众子集校验；任何隐藏层都需要“诱饵秘密”数据库与导出泄漏测试。

## 发布门槛

- 默认 CI 不调用真实模型；DeepSeek/Codex 实际调用必须显式开启并提供本机凭据。
- V2 协议、桌面、Worker、Python 和 Rust 测试全部通过后才生成 Windows x64 NSIS 包。
- 未配置提供者、额度耗尽、超时和能力缺失都必须明确失败，不自动切换提供者，也不伪造 AI 结果。
